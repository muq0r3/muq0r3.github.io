AFL，也就是 American Fuzzy Lop，是一个经典的覆盖率引导模糊测试工具。它通过不断变异输入、观察程序执行路径和崩溃情况，帮助研究人员发现解析器、文件处理程序和 C/C++ 程序中的潜在漏洞。

<!-- more -->

## 为什么学习 AFL

模糊测试的核心思想并不复杂：向程序输入大量自动生成或变异的数据，观察程序是否崩溃、卡死或出现异常行为。AFL 的优势在于它会利用覆盖率反馈保留“更有价值”的测试用例，从而比纯随机测试更高效。

学习 AFL 可以帮助理解：

- 程序输入如何触发不同执行路径。
- 覆盖率反馈如何指导测试用例变异。
- 崩溃样本如何被保存和复现。
- 安全测试中如何从工具结果回到漏洞根因分析。

## 基本概念

**目标程序** 是被测试的程序。它最好能从文件或标准输入读取数据，并且可以快速启动和退出。

**种子输入** 是模糊测试开始时使用的初始样本。好的种子通常能被目标程序正常解析，并覆盖基础逻辑。

**插桩编译** 是指用 AFL 提供的编译器包装器编译程序，让 AFL 能观察目标程序的执行路径。

**崩溃样本** 是导致目标程序异常退出的输入。后续分析时，需要尽量复现崩溃并定位触发路径。

## 最小使用流程

### 1. 准备目标程序

假设目标程序是 `target.c`，可以使用 AFL 的编译器进行编译：

```bash
afl-gcc -o target target.c
```

如果使用 C++，通常可以改用 `afl-g++`。

### 2. 准备种子输入

AFL 需要一个输入目录作为初始语料库：

```bash
mkdir in
echo "seed input" > in/seed1
```

种子不一定要复杂，但最好能让目标程序走到正常解析逻辑。

### 3. 启动模糊测试

基本命令如下：

```bash
afl-fuzz -i in -o out ./target
```

参数含义：

- `-i in`：指定输入目录。
- `-o out`：指定输出目录。
- `./target`：指定被测程序。

### 4. 观察运行状态

AFL 运行后会显示实时状态，包括执行速度、路径数量、崩溃数量和挂起数量。第一次学习时，可以重点关注：

- `total paths`：发现的路径数量。
- `unique crashes`：唯一崩溃数量。
- `exec speed`：每秒执行次数。
- `cycles done`：队列遍历轮次。

## 输出目录

运行下面的命令后：

```bash
afl-fuzz -i in -o out ./target
```

`out/` 目录通常会包含这些内容：

```text
out/
├── crashes/       # 导致崩溃的输入
├── hangs/         # 导致程序超时或挂起的输入
├── queue/         # AFL 保留下来的有趣测试用例
├── fuzz_bitmap    # 覆盖率相关状态
├── fuzzer_stats   # 模糊测试统计信息
└── plot_data      # 用于绘制进度图的数据
```

其中最常看的目录是 `crashes/`、`hangs/` 和 `queue/`。如果发现崩溃，下一步不是急着下结论，而是先复现：

```bash
./target < out/crashes/id:000000,sig:11,src:000000,time:1234,op:havoc,rep:2
```

复现后再配合调试器、ASan 或源码阅读定位根因。

## 下一步阅读

后续可以继续学习这些方向：

- AFL 的插桩机制和覆盖率反馈。
- 测试用例变异策略。
- crash triage 和最小化复现样本。
- AFL++ 的新特性和实际工程配置。
- 如何为复杂程序编写 harness。
